## 模块：输入与施法触发

> 说明：  
> - 本模块主要用于 **EditMode / 逻辑层测试**，并补充一项 **真机输入延迟检查**。  
> - 重点验证当前版本中的 Trigger 输入、冷却、防抖、长按策略以及输入响应时序是否符合设计。  
> - 执行测试前请保持 `Actual Outcome` 和 `Status` 为空。  
> - `Status` 建议使用：`Not Run`、`Pass`、`Fail`、`Blocked`、`N/A`。  
> - 若某项依赖当前版本中尚未确认实现的功能，请先标记为 `Blocked`，并补充实现核查链接或说明。
>
> 量化通过标准：
> - Trigger / 冷却 / 防抖类用例采用精确计数判定：合法施法次数必须等于预期次数，非法多触发次数必须为 `0`。
> - 冷却边界类用例只有在冷却结束前 `0` 次施法、冷却结束后 `1` 帧内即可触发首个合法施法时才算通过。
> - 对于 `100` 轮重复测试，允许多触发次数 = `0`，允许漏触发次数 <= `1`。
> - Trigger 到可见 Projectile 的延迟目标：轻负载场景 <= `120 ms`，正常对局场景 <= `150 ms`。
> - `20` 次重复延迟一致性目标：最大值与最小值之差 <= `50 ms`，且任意单次样本不得超过 `180 ms`。
